## A) How to Add the Next Case Study to My Portfolio

My portfolio is built on a repeatable case-study structure. Adding the next case means following the same four steps I used for the previous ones:

1. **Create a new route.** In the same project, add a new file under `src/routes/` (for example, `case-study-name.tsx`). This becomes `/case-study-name` on the live site.
2. **Reuse the case structure.** Every case follows the same sections:  
   - **Problem:** What pain point or opportunity the project addressed.  
   - **What I did:** Tools, models, data, and design decisions.  
   - **Result / lesson:** Outcome, metrics, or key takeaway.
3. **Match the existing voice and design.** Keep the direct, no-jargon tone and the same Tailwind + React component patterns. No need to redesign the site.
4. **Publish and update links.** Deploy through Lovable, then add the new case URL to the homepage-seo, homepage, or any navigation that lists work.

That is it. The next case is a content addition, not a rebuild.

## B) Next Case Study: AI-Powered Customer Support Response Assistant

**Working title:** AI-Powered Customer Support Response Assistant

**Problem:** Small support teams waste hours drafting repetitive replies to common questions. Response quality varies by agent, and slow replies hurt customer satisfaction.

**What I will do:** Build a support assistant that reads incoming customer messages, retrieves relevant past replies and help docs, and drafts a response in the team’s tone. The agent stays in control — they review, edit, and send. I will use retrieval-augmented generation (RAG) over a small knowledge base and a lightweight prompt pipeline.

**Expected outcome:** Cut first-response drafting time by roughly 50%, improve reply consistency, and free the team to handle complex tickets.
